# Bounded hit-authority observation probe

This tool is prepared for the [authority workbench](client-hit-authority-contract.md).
It has offline fixture coverage only; it has **not been attached to a client**.
The current research phase is static-only. The operator chooses when to collect.
The operator controls the game; agents do not launch it or interact with its UI.

## What it records

`scripts/re/frida/trace-hit-authority.js` observes five native boundaries:

| Entry VA | Input and output |
|---|---|
| `0x142187480` | World dispatch: selected decoded message identities and networking-mode byte |
| `0x141e91580` | Received-result processing: source entity, action key, target and before/after qualifiers |
| `0x141e69fb0` | Absolute pool assignment: resource owner, incoming values and pool before/after |
| `0x141e6a6b0` | Common local loss reducer: pool before/after, emitted only when current/carry changes |
| `0x14216e940` | Common instance sender: outgoing message ID and caller, without payload |

World observations cover `0x1ab/0x1af/0x1b0/0x1b1/0x1b3/0x1b4/0x1d1/0x1d2`.
Only selected numeric fields are exported, not arbitrary memory, keys, account data or socket buffers.
`0x1af` uses the record at message `+0x20`; record offsets are not wire offsets.
Optional control fields are null when their decoded admission conditions are absent.
`0x1ab`'s final words retain neutral names `field34/field36` pending independent consumer attribution.
Pool pointers identify the same storage within this process/session; no player entity ID is hardcoded.

`worldCallId` and `resultCallId` identify **same-thread nested native invocations**.
A null parent means no active observed invocation of that kind, not no earlier causal event.
These IDs are generated by the probe; they are neither network IDs nor server hit IDs.
`elapsedMs` uses `Date.now`, not server time, and does not measure a server tick interval.

## Operator procedure

1. Prepare one already-running **project-copy** client using the repository's normal
   [live-testing workflow](../dev/live-testing.md); identify its exact PID and confirm its executable location.
   Choose Predictive for the first experiment and record the selected mode explicitly.
   Record the repository revision, original executable SHA256, patched executable SHA256 and Frida version
   in an ignored sidecar. The original `Client/Game.exe` expected by this analysis has SHA256
   `78a0e227189c263658a7f65a02f086428b859bfc114ae8e7ce8aab721ebd48d5`.
   A patched executable has its own hash; five matching entry signatures alone do not attest the whole image.
2. From a repository root containing this probe and an existing Python/Frida environment, run the command below.
   During the window, use a short quiet control and then expose the player to one isolated Sand Spitter hit,
   if practical. Note other monsters, recovery, resource costs, avoidance and uncertainty.
   Keep the log local for inspection; report its path and those notes to the researcher.

```powershell
# Replace 12345 with the confirmed client PID. Never use process-name fallback or --follow here.
$clientPid = 12345
$hitLog = 'logs/hit-authority-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff') + '.jsonl'
if (Test-Path -LiteralPath $hitLog) { throw 'Choose a fresh log name; the runner appends.' }
.venv/Scripts/python.exe scripts/re/frida/run.py $clientPid scripts/re/frida/trace-hit-authority.js --seconds 60 --log $hitLog
```

Load this standalone script **without `common.js` or other probes**.
No dependency installation, client start or automatic process selection is part of this command.
The Python executable can be supplied from an existing environment outside this checkout.
Both the script and runner are time-bounded: the probe stops after 60 seconds, 1,000 regular events,
three read errors or excessive nesting; the runner detaches at 60 seconds or Ctrl-C.
Limits can terminate before a hit, so an early stop requires a new observation, not an absence conclusion.
Only the probe's own five hooks are detached; it never kills the client or calls a game function.
Frida instrumentation changes execution timing; this is not an uninstrumented timing measurement.

Expect `ready`, observed events and one `stopped` event inside Frida `send` envelopes.
`refused` means zero hooks were installed because module/signature verification failed.
Installation failure cleans up any hooks already installed and reports `install-error`.
External detach, process termination or runner shutdown can end a session without `stopped`.
The runner adds its own loaded/attached/detached lines; those are not combat observations.

## Interpretation limits

This is a decoded application-message/state trace, **not a TCP capture or complete message census**.
The common sender has direct/inline bypasses documented in `scripts/re/c2s_md.py`.
No observed outgoing ID therefore cannot prove that the client sent no per-hit report.
The local loss reducer also does not cover every possible resource write.
A callback can occur after the World invocation has returned; a null `worldCallId` is expected for that case.
No hook intercepts spatial contact or every action callback.
Do not infer per-event numerical prediction from a pool delta, or attribution from adjacent records.
Local-server traffic describes LocalExile's current producer, not the official server's behavior.
The log cannot replace missing official records or establish the server's internal damage algorithm.

Offline checks, with no client or Frida session:

```powershell
node --check scripts/re/frida/trace-hit-authority.js
node --test scripts/re/tests/hit_authority_probe.test.cjs
```

The two fixtures check nested identity/state observations and bounded cleanup/refusal, respectively.
They validate supplied mock inputs, not actual Frida ABI compatibility or a witnessed hit.
