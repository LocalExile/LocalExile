# 3.29.3c client diff (from 3.29.3b)

Read-only comparison of the official 3.29.3c client with the 3.29.3b archive this server targeted before the
migration. The official patch notes only say: "Added support for the upcoming announcement and new Supporter Packs."
Most of the change is a cross-game / ExileCon 2026 content preload, not new Path of Exile 1 gameplay.

## Version and container

| | 3.29.3b | 3.29.3c |
|---|---|---|
| Patch root | `https://patch.poecdn.com/3.29.3.3/` | `https://patch.poecdn.com/3.29.3.4/` |
| Patch protocol | 7 | 7 |
| Engine | 2.9.0 | 2.9.0 |
| `PathOfExile.exe` | 79,345,496 B | 79,394,136 B |
| `Content.ggpk` | 69,481,120,995 B | 71,546,555,532 B |
| Indexed files | 1,214,937 | 1,245,702 |
| Bundle files | 46,641 | 46,884 |

The GGPK gained 30,876 paths and lost 111 (net +30,765, about +1.92 GiB). Most additions are assets:
22,954 hideout terrain models, 2,929 microtransaction effects, 1,891 item models, 358 dialogue files and 332 pet
models. The only data-table path removed is `MicrotransactionChargeVariations.datc64` and its localized variants.

## Game data

No new PoE1 base items, skills, gems, monsters, maps, quests or passive nodes were added. `BaseItemTypes`,
`SkillGems`, `GrantedEffects`, `ActiveSkills`, `Mods` and `PassiveSkills` keep their row counts. `MonsterVarieties`
and `BaseItemTypes` changed only visual row references.

New content is concentrated in hideouts, microtransactions and one new NPC:

### New hideouts

| Hideout | `WorldAreas` row / hash | File | Unlock MTX |
|---|---|---|---|
| Labyrinth Hideout (`HideoutMaze_`) | 1677 / `22739` | `Metadata/Terrain/Hideouts/Maze/decoration.hideout` | 8417 |
| Apex of Divinity Hideout (`HideoutDivine`) | 1678 / `5338` | `Metadata/Terrain/Hideouts/Divine/decoration.hideout` | 8531 |
| Exilecon 2026 Hideout (`HideoutExilecon2026`) | 1679 / `10438` | `Metadata/Terrain/Hideouts/Exilecon26/decoration.hideout` | 8532 |

The old Exilecon23 hideout was re-indexed from `HideoutArea=1909` to `1912`; it remains disabled with the
"unsupported in this version... enabled in an upcoming patch" error. The three new hideouts insert at
`WorldAreas` 1677-1679, `Topologies` 2283-2285 and `Environments` 1055-1059, shifting later numeric references by
+3, +3 and +5 respectively.

The Labyrinth Hideout has a timed maze minigame: `MissionTimerTypes=HideoutMaze`, countdown and start sounds,
`ClientLeagueAction=MicrotransactionMazeHideoutEscapeAction`, a `MtxHideoutMazeLeaderboard` task, a Maze Reset
button, and the strings "{0} is first to exit the maze!" / "You escaped the maze in {0}!".

The Apex of Divinity Hideout has a built-in map device (`MapDevices=DivineHideoutBuiltInMapDevice`) and a new
trailing `HideoutDoodads` flag that is true only for that doodad.

### Puppet of Corruption

`NPCs` row 819 is `Metadata/Terrain/HideoutDecorations/Microtransactions/EdictCorruptionTrader/EdictCorruptionTrader_`,
name "Puppet of Corruption". Its dialogue offers Currency Exchange (`CurrencyExchangeWindow`), Purchase Items,
Manage Shop (`AsyncTradeStashWindow`) and Identify Items. Eight `NPCVendorDialogue` scripts handle listing, price
adjustment, sales in/out of zone, purchases and currency orders. It has 299 `NPCTextAudio` lines, male/female
greetings and goodbyes, and new quest flags for gender, first seen and intro seen.

This is a hideout shop / asynchronous trade and currency-exchange NPC. The server does not implement those screens
or scripts yet; it is separate from the existing direct player-trade flow.

### Hideout submission

Six new `BackendErrors` describe a hideout-submission flow: hideout does not exist, already submitted, no valid
submitted hideouts, cooldown, selected reward disabled, selected modifier set disabled. No new table was added; the
client-side flow is present, the server side is not implemented.

### Microtransactions

New `ShopTag` themes: `PoE2FullRelease`, `SeerOfTheMajiTheme`, `DreamkeeperTheme`, `SoulflameTheme`,
`NightfowlTheme`. The `Path of Exile 2 Full Release` category contains 56 items, including the five Archon sets:
Ash, Corruption, Divinity, Destruction (internal `EdictSpear`) and Rebirth.

Several old MTX lines were renamed/re-themed rather than newly authored: Chayula -> Dreamkeeper, Wildwood Seer ->
Seer of the Maji, Spirit Walker -> Spirit Warden, Stonebender -> Stonefist, Stygian -> Phantasmal, Divine ->
Radiant, King in the Mists -> Chaosborn Druid, Buccaneer -> Soulflame, Disease Vector -> Plaguebearer. The old
`MtxTypes` IDs are gone; saved cosmetics that reference them may need migration.

## Schema and extractor

Two tables changed layout:

| Table | 3.29.3b row | 3.29.3c row | Change |
|---|---:|---:|---|
| `HideoutDoodads` | 156 B | 157 B | trailing bool |
| `MapDevices` | 110 B | 126 B | trailing 16-byte foreign row |
| `MicrotransactionChargeVariations` | present | removed | table and localized files deleted |

The upstream dat-schema release from 2026-11-05 still has the old 156/110 layouts, so the repository schema needs
two local columns. With them, the extractor decodes 942 tables, 2 empty, 26 missing and 0 schema mismatches.
`extract-data.ps1` bumps its `tables` manifest entry to version 2 so an existing `data/` from 3.29.3b is not
silently reused.

Most of the 88 changed tables are numeric-reference shifts, not content: `BaseItemTypes` changed 4,654
`ItemVisualIdentity` references, `MonsterVarieties` 3,770 visual references, `UniqueStashLayout` 1,383,
`ItemVisualReplacement` 356, `SynthesisAreas` 167. All game data must be re-extracted together; mixing 3.29.3b and
3.29.3c tables misresolves rows. Existing hideout layouts are safe: all 1,571 common hideout-doodad models keep the
same `MtxTypeGameSpecific.HASH32`, and existing area/hideout hashes are unchanged.

## Client executable

The login key material is unchanged. The DER blob moved from `0x2fbf550` to `0x2fc91f0`, but the patcher finds it
by DER header and existing `data/login-keys.json` keys can be reused. The HNC 64-byte mask also kept its contents
(SHA-256 `0e88f29a...`) but moved from VA `0x142fe0da0` to `0x142feaed0`; `HncSender.MaskVa` must use the new
address. Other documented client addresses are 3.29.3b references and shift in 3.29.3c.

## Native verification (2026-11-06)

Login, character list, instance connect and `1_1_1` generation work with the 3.29.3c client. Area entry stops at the
loading screen with:

```
Unable to deserialise packet with pid 156. Last PID was 16
```

The client connected to `127.0.0.1:6112`, generated The Twilight Strand (seed 1585053215) and the Gateway created the
player, monsters, NPCs and items. The failure is in the client's instance/world pid dispatch after the
`0x1b3`/`0x2ba`/`0x2b9` burst. The 3.29.3c `0x1b3` reader (`0x141fe7b70`) is byte-identical to the 3.29.3b reader
except for shifted call targets; the compact-int/uint and message-header readers are also unchanged. The only `0x9c`
(156) in the outgoing stream is the low byte of the player type hash `0x3E99419C` in `0x02b9 create current player`
and a compact stat key in the final class-attributes packet. A fresh Frida dump of the 3.29.3c pump/object reader is
needed to identify the rejected packet; do not guess.

The optional native-control bridge is still pinned to 3.29.3b (`client-control.js` code signatures), so the native
check above uses the real client UI and logs, not the bridge. Update its addresses/signatures before using the bridge
with 3.29.3c.

## Frida probe (2026-11-06)

`run.py --follow` attached to the 3.29.3c client before launch (module base `0x7ff701370000`). The client reached
Lioneye's Watch and terminated with the same `pid 156` dialog. Hooks on the instance pump fallback (`0x1429A78A5`) and
the world group handler (`0x142F1E550`) produced no dispatch record before termination: the exception is raised by a
group/component reader before those hooks, not by the pump's unknown-id fallback. The next probe is the `0x2b9`
CreateObject blob reader (3.29.3b address `0x141EBE190`) to find which component under-reads or dereferences a null
pointer; more pump hooks are not useful.
