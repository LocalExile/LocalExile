# Unique jewels: catalogue and implementation roadmap

This page lists every unique jewel in the target 3.29.3b client and records what the server does with it.

The list and effect text are derived from Path of Building's `src/Data/Uniques/jewel.lua` (a read-only third-party reference under `Tools/PathOfBuilding`, not committed), cross-checked with the client tables `UniqueStashLayout`, `Words`, `BaseItemTypes`, `Mods`, `PassiveJewelSlots` and `PassiveJewelRadii`.

Rows with several `Variant:` lines list every variant; the unique item generator must choose one variant, not apply all of them. **Militant Faith is the exception: each item carries two distinct mods from its per-10-Devotion pool.** The status column is about the current server behaviour, not about whether the unique exists in the game. The client `UniqueStashLayout` has 202 jewel rows (190 distinct names, including alternate art and the repeated Grand Spectrum/Combat Focus/Lord of Steel rows); this catalogue lists the 185 distinct definitions in Path of Building's reference data.

The passive-socket implementation itself is documented in [protocol/15-progression.md](../protocol/15-progression.md) and tracked in [roadmap/unique-jewels.md](../../roadmap/unique-jewels.md).

## Status legend

| Status | Meaning |
|---|---|
| **Global** | The jewel has only unconditional character stats. The current socket/stat engine applies those mods; `/unique_jewel` is the dev source. |
| **Done** | The jewel is implemented and verified for the ordinary passive sockets. The item may still only be obtainable through a dev command, not a normal drop. |
| **Conditional** | Part of the effect is unconditional, but a condition (`if you have`, `recently`, `on kill`, per allocated node, ...) is not modelled. The current stat path would apply the mod unconditionally, so this jewel is not safe to use yet. |
| **Radius** | The jewel changes or reads passives in a radius. The radius/ring model and the 42 server-side rows are implemented; the 33 threshold items have client mods and server attribute counting, with skill-specific consumers still partial. See [radius-jewels.md](radius-jewels.md). |
| **Timeless** | A Legion timeless jewel: it replaces passive nodes with a legion seed/keystone set. The item, radius node stats and alternate tree are implemented; the conqueror keystones' special mechanics are not. |
| **Special** | The item is generated by a special mechanic. Impossible Escape and Rational Doctrine now have item sources; the rest are listed in the Special table and remain unmodelled. |
| **Cluster** | A cluster jewel. Voices and the ordinary cluster node/theme path work; the other unique cluster jewels add keystones and are not active. |
| **Abyss** | An abyss jewel, which belongs in an abyss socket on an item, not in the passive tree. Out of scope for this feature. |

### Reading the support status

- **Global** rows have a line-by-line status table after the catalogue; they can be created with `/unique_jewel`.
- **Conditional** rows list every mod, but **none is active in play** until its condition is modelled; the status names
  the blocker.
- **Radius** rows list every mod, but **none is active in play** beyond the fixed timeless radius; a general radius /
  threshold / node-modification model is still missing.
- **Timeless** rows have the item, radius node replacement and stat application; the conqueror keystones' special
  mechanics are listed in [timeless-jewel-list.md](timeless-jewel-list.md) and are not modelled.
- **Cluster** rows: Voices (three sockets plus empty passives) works; the other seven add keystones and are not active.

## Readiness

An estimate of how much of the unique-jewel catalogue the Gateway implements, counted per stat (one
mod can carry several) and weighted by jewel as well as by stat.

### How it is counted

Every stat a jewel's mods carry goes into one of three tiers:

- **in game** — it changes a hit, a defence, a pool, charges, flasks or a skill;
- **panel only** — the server computes it and sends it to the client, but nothing in the simulation
  reads it (a panel row, or a client-side visual such as character size);
- **unread** — no code path reads the stat.

A jewel's percentage is its in-game stats over all its stats. The catalogue percentage is the sum
over every jewel, so a jewel with six mods weighs more than one with a single stat; the jewel count
below weighs every jewel the same. Everything outside the Global set counts as 0: those jewels have
no radius, cluster, timeless or conditional logic and no `/unique_jewel` entry, so they cannot even
be obtained.

## How the current passive-jewel support works

- The ordinary tree has 21 large jewel sockets, exposed by the client as the `PassiveJewels1` inventory (Inventories.dat row 23, inventory id 24, 60x1).
- The pane cell `x` is the `PassiveJewelSlots.dat` row; that row's `Slot` column is the `PassiveSkills.dat` row of the socket node. Cluster expansion rows (21-56) and the three ascendancy charm sockets (57-59) are not ordinary sockets.
- A normal jewel (ItemClasses `Jewel`, not `Metadata/Items/Jewels/JewelPassiveTreeExpansion*`) can be placed into an allocated socket with C->S 0x2a, swapped with 0x4a, and picked up with 0x28. The server checks the socket is allocated and the level requirement, saves the jewel in the inventory, and applies its global mods like a worn item's (`ItemModStats`).
- Refunding a socket that still holds a jewel is refused until the jewel is taken out. A level trim prefers other leaves; if a jewel socket must be removed, the jewel is returned to the main inventory.
- Unique jewels use the same socket and stat path. The 42 Global rows have a dev source (`/unique_jewel`); there is no normal drop or vendor path yet. Radius and conditional rows are not active until their mechanics are modelled; timeless node stats are implemented, but the conqueror keystones are not.
- **Unique art** comes from `UniqueJewelVisuals.cs`, generated by `scripts/re/unique_jewels.py` from the client's `UniqueStashLayout`, `Words` and `ItemVisualIdentity`: every one of the 190 unique jewels the stash layout lists, by name, with its `ItemVisualIdentity` HASH16. `/unique_jewel`, `/adorned` and `/voices` all take the icon from it, so a jewel without an entry falls back to its base type's art instead of a wrong picture.
- **Large cluster jewels** (Voices for now) go into the six large tree sockets (pane cells 11, 12, 13, 15, 17, 20). `PassiveTree` knows the expansion cells a socket creates (`ClusterSlots`: a large one makes three medium cells, a medium one a small cell), the node of each cell (`ClusterNodeForSlot`) and the cell's parent (`ClusterParent`); `/voices [1|3|5|7]` makes the item. A socketed large cluster jewel opens its three medium cells for normal jewels (`ClusterSlotOpen`): they are placed like tree jewels and their global mods count, and they stop counting when the cluster jewel leaves. The cluster's own passives are allocated through the client (C->S 0x34 with the expansion flag, its own small ids) and saved with the character; the tree message's third u16 list carries them.

## Done unique jewels

The Adorned is the pilot unique jewel: the server creates a corrupted unique Crimson Jewel with a developer-selectable 0-1000% value (the normal item range is 0-100%) and scales corrupted magic jewels in ordinary passive sockets. Live check: a corrupted magic jewel gave +15% fire resistance, The Adorned at 100% made it +30% (225% -> 240% -> 255%). Cluster-socket jewels are not covered yet.

`alternate_passive_skills`) and its seed handling are the closest open reference for the mechanic; it has nothing for
cluster jewels.

## Notes on effects that need a different model

- **"In Radius" and threshold jewels** need the set of allocated passive nodes inside the jewel radius. The client packed graph has group coordinates and node orbit/position; `PassiveJewelRadii.dat` has Small/Medium/Large/VeryLarge radii in the same units.
- **Node-modifying jewels** (for example Lioneye's Fall, Elegant Hubris) need modifier flags or alternate stat rows; Lioneye's Fall's item source and client conversion are present, but its server flag model is missing. Might of the Meek's passive-effect and notable-suppression override is implemented in the radius pilot.
- **Granted keystone/notable** jewels need to add a passive node or a special stat that is not on the graph; the tree allocated list is currently the source of truth.
- **Conditional stats** need conditions evaluated at the point of use (per allocated node, per item, per recent kill, low life, charges, and so on), not at login.
- **Timeless jewels** need the legion seed, the alternate passive graph and the keystone substitution rules.
